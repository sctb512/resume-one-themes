Preserved design
The primary structure is a spacious, left-aligned single column: identity
and summary in the header, ruled section headings, individual cards for
work/education/projects/volunteer and simpler information modules, skill
keyword chips and language chips. The first-choice family is still Nunito,
including all four requested upright weights 400/600/700/800, instantiated
and renamed into independent Resume One Californian Nunito W400/W600/W700/
W800 families; see FONTS.txt and OFL.txt for the full source/rename lineage.
At 96 CSS px/in, the original 15px body, 48px name, 28px section title,
22px item title and 14px metadata map to 11.25/36/21/16.5/10.5pt. The body
line-height 1.8 and name line-height 1.2 are retained. Original 60px/50px
screen padding and 50px section gaps map to 15.875/13.229mm and 13.229mm.
Cream #FFF8F1, orange #EA580C, amber #D97706, brown #4D3319, dark amber
#92400E, pale orange #FED7AA and pale cream #FEF5E7 remain explicit tokens.
The newly supported independent label role uses the source 20px/600
(15pt/600), summary uses 16px/400 (12pt/400), and sideDate uses 14px/600
(10.5pt/600), all with the source inherited line-height 1.8. sideDate only
styles left/right standalone dates; inline dates still use meta. Original
name tracking -0.5px/48px is -1/96em (-0.375pt at 36pt); section-title
tracking -0.3px/28px is -3/280em (-0.225pt at 21pt). Both now use supported
trackingEm. textTransform remains none, preserving original text case.

Source-literal role color update (2026-10-30; exports pending)
The complete pinned src/Resume.jsx was reviewed again, including every
styled declaration and all module call sites. Five role foregrounds now
use typography.<role>.color rather than contrast-adjusted semantic tokens:
- name #D97706: Name, line 42; identity in the header only (line 285).
- sectionTitle #EA580C: StyledSectionTitle, line 96; the same component is
  used for every original module heading, with no regional variant.
- label #92400E: Tagline, line 49; basics.label only (line 286).
- summary #4D3319: Summary, line 58; basics.summary only (line 287).
- sideDate #92400E: ItemDate, line 142; work, education, projects and
  volunteer standalone dates use this same component. Inline auxiliary
  dates still use meta and are not covered by this literal.
These are exact CSS foreground declarations, not sampled or blended
approximations. The new explicit-color contract preserves them without
automatic contrast rewriting. This resolves the name/body and label/accent
foreground coupling and prevents section-title/summary/date foreground
darkening; it does not restore their missing surfaces or alpha treatment.
Tagline opacity 0.9 (line 52) and ItemDate opacity 0.8 (line 143) remain
unrepresented, so their final composited appearance is still not matched.
No flattened opacity color was invented for the absent gradient or pill.

body, itemTitle and meta intentionally have no explicit color: body spans
ItemDescription / HighlightsList li #4D3319 (lines 168/182) and SimpleCard p
#78350F (line 254), while Layout inherits #3D2A1F (line 20). itemTitle spans
ItemTitle / SimpleCard h4 #D97706 (lines 134/247) and SkillCategory h4
#EA580C (line 209). meta spans contact links #D97706 (line 73), subtitles
#78350F (line 153), locations #A16207 with opacity 0.9 (lines 159/162),
and small-card auxiliary text #78350F (line 254). A single global literal
would incorrectly erase these differences, even in a single-column theme.
Those roles retain the existing semantic colors; independent module/field
colors, link/chip colors and opacity remain renderer/spec blockers.

Follow-up CLI validation and PDF/DOCX exports used the role-color-capable
renderer and this exact manifest. The English all-module fixture generated
three PDF pages and three LibreOffice-rendered DOCX pages; the short Chinese
fixture generated one page in each format. All eight page images were
inspected. A later short-Chinese DOCX check explicitly splits missing-glyph
spans into real upright Noto Sans SC runs, avoiding reader-synthesized CJK
bold. These export checks do not certify the original theme's appearance.

Enumerated differences and renderer limits
1. The original gradient header (#FEF5E7 to #FEF0DC), 40px inner padding,
   20px rounded corners and amber web shadow are unavailable. The header
   stays a full-width, unboxed semantic header. No unsupported decorations
   or arbitrary CSS are emitted. The pale cream canvas uses the gradient's
   first endpoint, without claiming a gradient rendering.
2. Summary remains associated with the header, but the renderer places
   contacts before the summary; upstream puts summary before contacts.
   Its original 16px/400 size and the separate 20px/600 tagline are now
   declared through summary and label respectively. The white translucent
   inset, 20px padding, 12px radius and 4px amber left border remain
   unavailable, as do the tagline's opacity and independent margins. Its
   declared foreground is now exactly #92400E; alpha composition is not.
3. Source work/education/project/volunteer cards are white, borderless,
   padded 30px, radius 16px and softly shadowed. Simple cards use 24px,
   radius 14px. Supported cards use a thin rectangular border, 8pt inner
   horizontal padding and the renderer's readable, lightly tinted paper.
   Web shadows, radii, individual padding, 40px item gaps, hover transforms
   and transitions are unavailable and omitted. Large type, generous line
   height and section gaps retain the spacious humanist hierarchy.
4. Skills cannot combine an outer card and nested chips in one module.
   Keyword chips are retained; the source category's padded shadowed card
   is omitted. Language names use chips, with fluency retained as separate
   semantic text rather than combined inside each chip. Chip gradients
   (#FEF3C7 to #FDE68A), 12px radius, 10px/18px padding and hover effects
   become the renderer's flat, bounded text backgrounds. Interest cards
   and reference cards remain distinct from the chip modules.
5. Right-side dates for work/education/projects/volunteer retain their
   position and independent source 14px/600 sideDate role, but lose the
   #FEF3C7 pill, 20px radius and source opacity. Auxiliary dates in simple
   cards remain inline and use meta, not sideDate. A long date may wrap
   under its title to preserve content; no white-space:nowrap is imposed.
6. Exact name, section-title, label, summary and standalone-date foreground
   declarations are now independent, as documented above. Body, itemTitle
   and meta remain globally shared across source elements with different
   colors and therefore deliberately keep the old semantic-color behavior.
   The common body ink #4D3319 still cannot express SimpleCard p #78350F
   or inherited #3D2A1F; a global itemTitle literal cannot distinguish
   amber #D97706 titles from orange #EA580C skill categories. Auxiliary
   text still cannot separate subtitle #78350F, location #A16207 and
   contact-link #D97706. The omitted role colors may still be contrast
   adjusted by the renderer, unlike the five explicit role literals.
7. Section rules use the original pale orange #FED7AA, but their supported
   0.6pt thickness differs from the source 3px (2.25pt) border and fixed
   12px padding. Contact links use inline text with semantic separators,
   without the original amber backgrounds, rounded 8px contact boxes,
   per-link 8px/16px padding or 20px flex gaps. Star-shaped highlight
   markers become standard semantic bullets.
8. Source negative letter spacing (-0.5px name, -0.3px section title) now
   maps to the exact em ratios above. DOCX rounds character spacing to
   1/20pt; it cannot exactly store -0.375pt or -0.225pt, so final Word
   spacing remains a separate check. Italic roles are unsupported and
   not emitted; this source requests upright fonts only.
   Separate organization/subtitle, skill-title and small-card font roles
   still share supported roles. Their original 18px title and
   14px small-card body sizes cannot be configured independently.
9. The upstream component fixes module order in React. The manifest offers
   modules in that order, but the renderer preserves existing Resume JSON
   order and its semantic item labels/field mappings. Additional standard
   content stays visible, including fields upstream conditionals omit;
   no content is added to the theme or removed from the resume.
10. The web page's 820px maximum width and special white print background
    with 40px/30px padding become explicit A4 pagination and stable screen
    cream paper. Both pagination flags remain enabled. Earlier CLI stress
    evidence exposed CW10: an oversized first card could leave the section
    heading alone on a page. The main agent has since implemented shared
    oversized-card pagination changes; those historical outputs do not
    establish the current behavior. This font/role update performs no new
    pagination export and makes no new pagination acceptance claim.
    The renderer's page footer is application controlled. Letter QA uses
    a separate theme copy; the package defaults to A4.
11. Nunito has no CJK glyphs; Chinese uses the application's explicit Noto
    fallback rather than the web operating-system fallback chain. The
    variable source was initially instantiated at fixed weights. CW09
    now renames each approved static face to its own family W400/W600/
    W700/W800. Only name metadata and the required head checksum adjustment
    change; all outline, metric, shaping and permission tables remain
    byte-identical. Original copyright, full OFL, fsType=0 and real weights
    400/600/700/800 are preserved. This removes the candidate's shared
    family/bold-slot collision by giving each face a distinct family key.
    Actual DOCX slot embedding, weight selection and Word reflow are still
    the main agent's checks; this update claims no new DOCX/PDF results or
    pixel equivalence. No local or system font installation is performed.

Follow-up font identity audit (2026-10-30): all four final static faces were
checked across every name-table platform/encoding/language record. nameID
18 and 25 are absent; existing WWS names 21/22 already match the independent
aliases and subfamilies. The helper now remaps existing optional compatible
full names and variation PostScript prefixes if present. A separate QA
regeneration reproduced all four current fonts byte-for-byte, so their
asset SHA-256 values and family names remain unchanged. Copyright/license
strings, full OFL, outlines, metrics, actual weights and fsType are preserved.
This metadata check does not change the draft or acceptance status.

This is an adaptation with explicit approximations, not a pixel-identical
port or a claim of full native GUI, Word, packaging or release acceptance.
Those checks remain with the main task. No remote images, private resumes,
runtime font requests or Resume JSON style extensions are used.

Preserved design
The primary structure is a spacious, left-aligned single column: identity
and summary in the header, ruled section headings, individual cards for
work/education/projects/volunteer and simpler information modules, skill
keyword chips and language chips. The first-choice family is still Nunito,
including all four requested upright weights 400/600/700/800, instantiated
and renamed into independent Resume One Californian Nunito W400/W600/W700/
W800 families; see FONTS.txt and OFL.txt for the full source/rename lineage.
At 96 CSS px/in, the original 15px body, 48px name, 28px section title,
22px item title and 14px metadata map to 11.25/36/21/16.5/10.5pt. The body
line-height 1.8 and name line-height 1.2 are retained. Original 60px/50px
screen padding and 50px section gaps map to 15.875/13.229mm and 13.229mm.
Cream #FFF8F1, orange #EA580C, amber #D97706, brown #4D3319, dark amber
#92400E, pale orange #FED7AA and pale cream #FEF5E7 remain explicit tokens.
The newly supported independent label role uses the source 20px/600
(15pt/600), summary uses 16px/400 (12pt/400), and sideDate uses 14px/600
(10.5pt/600), all with the source inherited line-height 1.8. sideDate only
styles left/right standalone dates; inline dates still use meta. Original
name tracking -0.5px/48px is -1/96em (-0.375pt at 36pt); section-title
tracking -0.3px/28px is -3/280em (-0.225pt at 21pt). Both now use supported
trackingEm. textTransform remains none, preserving original text case.

Source-literal role color update (2026-10-30; exports pending)
The complete pinned src/Resume.jsx was reviewed again, including every
styled declaration and all module call sites. Five role foregrounds now
use typography.<role>.color rather than contrast-adjusted semantic tokens:
- name #D97706: Name, line 42; identity in the header only (line 285).
- sectionTitle #EA580C: StyledSectionTitle, line 96; the same component is
  used for every original module heading, with no regional variant.
- label #92400E: Tagline, line 49; basics.label only (line 286).
- summary #4D3319: Summary, line 58; basics.summary only (line 287).
- sideDate #92400E: ItemDate, line 142; work, education, projects and
  volunteer standalone dates use this same component. Inline auxiliary
  dates still use meta and are not covered by this literal.
These are exact CSS foreground declarations, not sampled or blended
approximations. The new explicit-color contract preserves them without
automatic contrast rewriting. This resolves the name/body and label/accent
foreground coupling and prevents section-title/summary/date foreground
darkening; it does not restore their missing surfaces or alpha treatment.
Tagline opacity 0.9 (line 52) and ItemDate opacity 0.8 (line 143) remain
unrepresented, so their final composited appearance is still not matched.
No flattened opacity color was invented for the absent gradient or pill.

body, itemTitle and meta intentionally have no explicit color: body spans
ItemDescription / HighlightsList li #4D3319 (lines 168/182) and SimpleCard p
#78350F (line 254), while Layout inherits #3D2A1F (line 20). itemTitle spans
ItemTitle / SimpleCard h4 #D97706 (lines 134/247) and SkillCategory h4
#EA580C (line 209). meta spans contact links #D97706 (line 73), subtitles
#78350F (line 153), locations #A16207 with opacity 0.9 (lines 159/162),
and small-card auxiliary text #78350F (line 254). A single global literal
would incorrectly erase these differences, even in a single-column theme.
Those roles retain the existing semantic colors; independent module/field
colors, link/chip colors and opacity remain renderer/spec blockers.

Enumerated differences and renderer limits
1. The original gradient header (#FEF5E7 to #FEF0DC), 40px inner padding,
   20px rounded corners and amber web shadow are unavailable. The header
   stays a full-width, unboxed semantic header. No unsupported decorations
   or arbitrary CSS are emitted. The pale cream canvas uses the gradient's
   first endpoint, without claiming a gradient rendering.
2. Summary remains associated with the header, but the renderer places
   contacts before the summary; upstream puts summary before contacts.
   Its original 16px/400 size and the separate 20px/600 tagline are now
   declared through summary and label respectively. The white translucent
   inset, 20px padding, 12px radius and 4px amber left border remain
   unavailable, as do the tagline's opacity and independent margins. Its
   declared foreground is now exactly #92400E; alpha composition is not.
3. Source work/education/project/volunteer cards are white, borderless,
   padded 30px, radius 16px and softly shadowed. Simple cards use 24px,
   radius 14px. Supported cards use a thin rectangular border, 8pt inner
   horizontal padding and the renderer's readable, lightly tinted paper.
   Web shadows, radii, individual padding, 40px item gaps, hover transforms
   and transitions are unavailable and omitted. Large type, generous line
   height and section gaps retain the spacious humanist hierarchy.
4. Skills cannot combine an outer card and nested chips in one module.
   Keyword chips are retained; the source category's padded shadowed card
   is omitted. Language names use chips, with fluency retained as separate
   semantic text rather than combined inside each chip. Chip gradients
   (#FEF3C7 to #FDE68A), 12px radius, 10px/18px padding and hover effects
   become the renderer's flat, bounded text backgrounds. Interest cards
   and reference cards remain distinct from the chip modules.
5. Right-side dates for work/education/projects/volunteer retain their
   position and independent source 14px/600 sideDate role, but lose the
   #FEF3C7 pill, 20px radius and source opacity. Auxiliary dates in simple
   cards remain inline and use meta, not sideDate. A long date may wrap
   under its title to preserve content; no white-space:nowrap is imposed.
6. Exact name, section-title, label, summary and standalone-date foreground
   declarations are now independent, as documented above. Body, itemTitle
   and meta remain globally shared across source elements with different
   colors and therefore deliberately keep the old semantic-color behavior.
   The common body ink #4D3319 still cannot express SimpleCard p #78350F
   or inherited #3D2A1F; a global itemTitle literal cannot distinguish
   amber #D97706 titles from orange #EA580C skill categories. Auxiliary
   text still cannot separate subtitle #78350F, location #A16207 and
   contact-link #D97706. The omitted role colors may still be contrast
   adjusted by the renderer, unlike the five explicit role literals.
7. Section rules use the original pale orange #FED7AA, but their supported
   0.6pt thickness differs from the source 3px (2.25pt) border and fixed
   12px padding. Contact links use inline text with semantic separators,
   without the original amber backgrounds, rounded 8px contact boxes,
   per-link 8px/16px padding or 20px flex gaps. Star-shaped highlight
   markers become standard semantic bullets.
8. Source negative letter spacing (-0.5px name, -0.3px section title) now
   maps to the exact em ratios above. DOCX rounds character spacing to
   1/20pt; it cannot exactly store -0.375pt or -0.225pt, so final Word
   spacing remains a separate check. Italic roles are unsupported and
   not emitted; this source requests upright fonts only.
   Separate organization/subtitle, skill-title and small-card font roles
   still share supported roles. Their original 18px title and
   14px small-card body sizes cannot be configured independently.
9. The upstream component fixes module order in React. The manifest offers
   modules in that order, but the renderer preserves existing Resume JSON
   order and its semantic item labels/field mappings. Additional standard
   content stays visible, including fields upstream conditionals omit;
   no content is added to the theme or removed from the resume.
10. The web page's 820px maximum width and special white print background
    with 40px/30px padding become explicit A4 pagination and stable screen
    cream paper. Both pagination flags remain enabled. Earlier CLI stress
    evidence exposed CW10: an oversized first card could leave the section
    heading alone on a page. The main agent has since implemented shared
    oversized-card pagination changes; those historical outputs do not
    establish the current behavior. This font/role update performs no new
    pagination export and makes no new pagination acceptance claim.
    The renderer's page footer is application controlled. Letter QA uses
    a separate theme copy; the package defaults to A4.
11. Nunito has no CJK glyphs; Chinese uses the application's explicit Noto
    fallback rather than the web operating-system fallback chain. The
    variable source was initially instantiated at fixed weights. CW09
    now renames each approved static face to its own family W400/W600/
    W700/W800. Only name metadata and the required head checksum adjustment
    change; all outline, metric, shaping and permission tables remain
    byte-identical. Original copyright, full OFL, fsType=0 and real weights
    400/600/700/800 are preserved. This removes the candidate's shared
    family/bold-slot collision by giving each face a distinct family key.
    Actual DOCX slot embedding, weight selection and Word reflow are still
    the main agent's checks; this update claims no new DOCX/PDF results or
    pixel equivalence. No local or system font installation is performed.
